# FW-NetPulse

FW-NetPulse — локальный монитор игровой сети для Windows. Он показывает реальный ICMP-пинг, время TCP-подключения к игровому порту, потери, джиттер, маршрут до сервера и найденные окна игры. Программа ориентирована на Forsaken World / FW-Rebirth, но адрес сервера, порты и имена процессов можно изменить в `config.json`.

Готовая переносимая версия не требует Python. Скачайте ZIP из раздела **Releases**, распакуйте его полностью и запустите `FW-NetPulse.exe`.

## Что умеет программа

- Проверяет ICMP-задержку каждые 500 мс и TCP-доступность игрового порта каждую секунду.
- Автоматически находит процессы `pem.exe`, `pemv.exe`, `elementclient.exe` и `patcher.exe`.
- Сопоставляет процессы с их TCP-соединениями и выбирает игровой порт раньше служебных соединений.
- Показывает каждое найденное окно игры. Если несколько окон используют один адрес и порт, их сетевой пинг одинаков: Windows не хранит отдельный RTT для каждого процесса.
- Автоматически создаёт отдельный график для каждого игрового окна и отдельный набор ICMP/TCP/Smart MTR-измерений для каждого уникального зеркала.
- Добавляет вкладки игровых окон над Smart MTR и журналом аномалий, чтобы вручную сравнивать четыре разных входа в игру.
- Позволяет скрывать основной график, мини-графики, карточки окон, оптимизатор, Smart MTR и журнал. Настройки сохраняются в браузере.
- Обычный клик по карточке мгновенно выбирает нужное окно и его пинг; кнопка с глазом выводит само окно игры на передний план.
- Во время выделения текста обновление панели ставится на паузу, поэтому адреса и результаты можно нормально скопировать.
- Строит графики за 1, 5, 10 и 15 минут. Длинные интервалы объединяются по медиане, поэтому линия не дёргается от каждого единичного замера.
- Показывает скачки отдельно, а реальные неответившие ICMP/TCP-пробы отмечает красной линией и маркерами.
- Выполняет непрерывный Smart MTR и старается отличать настоящие потери от ограничения ответов ICMP на промежуточном маршрутизаторе.
- Записывает сетевые фризы в локальную SQLite-базу и экспортирует историю в CSV или JSON.
- Показывает компактный браузерный оверлей и отдельный настольный HUD.
- Анализирует измерения и предлагает проверить домашнюю сеть, игровой сервер, точечный DPI-профиль или внешний релей.
- Сравнивает режимы по медиане, P95, джиттеру и потерям. Меньшая итоговая оценка означает более стабильное соединение.

## Быстрый запуск готового релиза

1. Откройте страницу **Releases** репозитория.
2. Скачайте `FW-NetPulse-v1.1.2.0-win64.zip` и файл `SHA256SUMS.txt`.
3. Распакуйте ZIP в отдельную папку. Не запускайте один EXE прямо из архива.
4. Запустите `FW-NetPulse.exe`.
5. Веб-панель откроется по адресу http://127.0.0.1:8899.
6. Для поиска процессов, запущенных с повышенными правами, и для управления обходом запускайте программу от имени администратора.

Архив не подписан коммерческим сертификатом, поэтому Windows SmartScreen может показать предупреждение. Сверьте SHA-256 скачанного ZIP с опубликованным `SHA256SUMS.txt`.

## Как читать результаты

### ICMP и TCP

ICMP показывает обычную сетевую задержку до IP. TCP показывает время установления нового соединения с игровым портом. TCP-линия может иметь технические промежутки: отсутствие пробы не считается потерей. Красная отметка появляется только тогда, когда проба действительно была отправлена и не получила ответ.

### Smart MTR

Большой процент потерь на одном промежуточном узле не всегда означает проблему. Маршрутизатор может ограничивать ответы на диагностический ICMP, продолжая нормально передавать игровой трафик. Потеря считается подозрительной, когда она продолжается на следующих узлах и на конечном сервере.

Подписи географии строятся по IP и имени узла эвристически. Это полезная подсказка, но не точная GeoIP-база.

### Несколько окон и зеркал

Если окна подключены к разным `IP:порт`, FW-NetPulse параллельно измеряет каждый путь и показывает отдельные графики, маршруты и события. Если два окна используют одно зеркало, вкладки остаются отдельными, но сетевые пробы переиспользуются: это уменьшает нагрузку и исключает искусственную разницу между одинаковыми путями.

Неактивное зеркало, которое больше не выбрано и не является резервной целью, сохраняет измерения в течение минуты, после чего его фоновые службы останавливаются. По умолчанию одновременно поддерживается до восьми уникальных адресов; лимит задаётся параметром `monitoring.multi_client_max_endpoints`.

### Точечный DPI-обход

FW-NetPulse запускает `winws` только для автоматически найденных игровых IPv4-адресов и портов из `optimizer.game_ports`. Он не перенаправляет весь интернет и не является VPN.

- Нужны права администратора.
- После смены профиля необходимо переподключиться к игровому серверу.
- Антивирус может классифицировать WinDivert как RiskTool/PUA, поскольку драйвер перехватывает пакеты.
- Обход не гарантирует уменьшение пинга и помогает только при определённых видах фильтрации TCP.
- Перед использованием проверьте правила игры и местное законодательство.

### Игровой релей WireGuard

Релей действительно меняет внешний маршрут, но сервер-релей не входит в комплект. Нужны официальный WireGuard for Windows, собственный сервер и конфигурация в `optimizer.relays`.

FW-NetPulse принимает только конфигурации, где `AllowedIPs` в точности содержит игровые адреса с маской `/32`. Маршрут `0.0.0.0/0` отклоняется, чтобы случайно не отправить через релей весь интернет. Подробности находятся в [ОПТИМИЗАЦИЯ_МАРШРУТА.md](ОПТИМИЗАЦИЯ_МАРШРУТА.md).

## Настройка

Основные параметры находятся в `config.json`:

- `target_server` — резервный IP, порт и название сервера;
- `monitoring.game_process_names` — точные имена EXE игровых клиентов;
- `monitoring.ping_interval_ms` — частота ICMP-проб;
- `monitoring.mtr_interval_s` и `max_hops` — параметры трассировки;
- `monitoring.multi_client_max_endpoints` — максимальное число параллельно измеряемых игровых зеркал;
- `web.port` — порт локальной панели;
- `optimizer.game_ports` — разрешённые игровые TCP-порты;
- `optimizer.relays` — заранее подготовленные WireGuard-конфигурации.

Закрытые ключи WireGuard храните только в отдельном `.conf` вне репозитория. Никогда не публикуйте токены GitHub, пароли и приватные ключи.

## Запуск из исходников

Требования: Windows 10/11 x64 и Python 3.11 или новее. Сторонние Python-библиотеки для запуска не нужны.

```powershell
python run_monitor.py
```

Или запустите `Start_Network_Monitor.bat`. Этот BAT-файл предназначен только для разработчика; пользователю готового релиза Python не нужен.

## Тесты

```powershell
python -m unittest discover -s tests -p "test_*.py" -v
powershell -ExecutionPolicy Bypass -File .\test_optimizer_ui.ps1
npm install
powershell -ExecutionPolicy Bypass -File .\test_multi_client_ui.ps1
```

Последняя команда проверяет четыре игровых окна, отдельные графики и реальное переключение PID и адреса API одним кликом. Node.js нужен только разработчику для браузерного теста и не требуется пользователю готового EXE.

После сборки дополнительно запускается проверка переносимого EXE:

```powershell
powershell -ExecutionPolicy Bypass -File .\test_portable.ps1
```

## Сборка переносимой версии

1. Установите PyInstaller:

   ```powershell
   python -m pip install -r requirements-build.txt
   ```

2. Скачайте проверенную Windows-сборку `zapret-discord-youtube` и укажите путь:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\build_portable.ps1 -ZapretSourceDir "C:\Путь\к\zapret-discord-youtube"
   ```

Скрипт создаст чистую папку `release/FW-NetPulse-vX.Y.Z.W-win64`, ZIP-архив и `SHA256SUMS.txt`. Локальная база истории, кэш Python и старые сборки в архив не попадают.

## Безопасность и приватность

- Панель слушает только `127.0.0.1` по умолчанию.
- Управляющие POST-запросы принимаются только от локального клиента и локальной страницы.
- Телеметрия и история не отправляются автору программы или в облако.
- База `data/network_history.db` остаётся на компьютере пользователя.
- Программа выполняет сетевые ICMP/TCP-пробы и обратные DNS-запросы к узлам маршрута.
- Изменение TCP-параметров Windows, DPI-профили и WireGuard требуют осознанного подтверждения и прав администратора.

Диагностика основана на измерениях и эвристиках. Она не может доказать действия провайдера и не может вручную выбрать промежуточные маршрутизаторы за пределами вашей локальной сети.
